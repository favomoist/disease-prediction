# AI Disease Prediction — Local Research Demo

A fully local, offline disease-prediction web app built with React + TypeScript + Vite on the frontend and FastAPI + XGBoost + SHAP + K-Means + Apriori on the backend.

This project uses a local Ollama model (`qwen2.5:7b`) only for:

- extracting structured facts from a free-text symptom description
- explaining an already-computed ML result in plain language

It does not use Ollama to predict the disease itself.

> Disclaimer: This is a research and education project. Outputs are statistical ML results, not medical diagnoses or treatment recommendations. Always consult a licensed clinician.

---

## Features

- Upload and inspect CSV datasets
- Automatically detect feature types
- Train and evaluate an XGBoost disease classifier
- View SHAP feature explanations
- Explore cluster summaries and association rules
- Use local Ollama for text extraction and explanation
- Check backend-to-Ollama connectivity in the UI

- Python 3.10+

## Local setup

### 1) Install and start Ollama

On Windows PowerShell:

```powershell
ollama serve
ollama pull qwen2.5:7b
```

### 2) Backend setup

```powershell
cd c:\Main\proj\disease-prediction\backend
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 3) Generate the dataset

```powershell
cd ..\data
python generate_dataset.py --rows 5200 --out patients.csv
```

### 4) Train the model

```powershell
cd ..\backend
python train.py --csv ..\data\patients.csv
```

### 5) Start the backend API

```powershell
cd c:\Main\proj\disease-prediction\backend
.\.venv\Scripts\Activate.ps1
uvicorn main:app --reload --port 8000
```

Health check:

```powershell
curl http://localhost:8000/api/health
```

### 6) Start the frontend

In a second terminal:

```powershell
cd c:\Main\proj\disease-prediction\frontend
npm install
npm run dev
```

Then open:

```text
http://localhost:5173
```

## How the app works

### Prediction flow

- upload a CSV dataset
- select a patient row
- optionally enter a free-text symptom description
- run the prediction pipeline
- inspect the model output and explanatory signals

### Results page includes

- patient info
- top 3 predicted diseases and probabilities
- SHAP positive and negative contributors
- extracted facts from Ollama
- contradictions between CSV data and text input
- plain-language explanation from Ollama
- cluster assignment and matched association rules
- convergence score breakdown

### Pattern Analysis page

Displays discovered cluster summaries and association rules across the dataset.

### Model Performance page

Shows metrics such as accuracy, precision, recall, F1, ROC-AUC, confusion matrix, and per-class report.

---

## Ollama role and status

The local model is used for exactly two bounded tasks:

1. Extract structured facts from the free-text description.
2. Explain the already-computed model output in plain language.

It is not used to generate disease predictions or probabilities.

The sidebar badge is connected to the backend health endpoint, which checks Ollama directly. The UI will show:

- `Ollama Connected` when the local Ollama server is reachable and the model is present
- `Ollama Offline` when the service is unavailable
